# Production checklist

## Necessity

- [ ] The functionality is required.
- [ ] Standard-library and existing-dependency alternatives were considered.
- [ ] The local implementation trade-off was considered.

## Maintenance and governance

- [ ] Maintainers and ownership are identifiable.
- [ ] Release and issue history are appropriate for the project.
- [ ] Security reporting information is available or the absence is accepted.
- [ ] The project has a plausible continuity story.

## Implementation

- [ ] Unsafe code was identified and assessed.
- [ ] Build scripts and procedural macros were assessed.
- [ ] Native dependencies and FFI were assessed.
- [ ] Sensitive capabilities are understood.

## Dependency graph

- [ ] Default and optional features were reviewed.
- [ ] Normal, build, and development edges were reviewed.
- [ ] Duplicate versions were reviewed.
- [ ] Dependency sources meet policy.

## Evidence and legal fit

- [ ] Known advisories were checked.
- [ ] License terms meet policy.
- [ ] Provenance and publishing information were reviewed.
- [ ] Relevant audits or external reviews were evaluated for version coverage.

## Decision

- [ ] Decision and rationale were recorded.
- [ ] Accepted risks and controls were recorded.
- [ ] An owner and review trigger were assigned.
- [ ] A replacement strategy is understood for high-impact dependencies.

# Supply Chain Attacks

## Vulnerability

The published code contains an exploitable defect or an intentionally vulnerable component.

## Compromise

An attacker obtains influence over source, publishing, or the build pipeline.

## Abandonment

The crate no longer receives the maintenance needed by your production system.

These risks can coexist, and each requires different evidence.

## The Problem

How to review the code?

[Adam Harvey](https://lawngno.me/blog/2024/06/10/divine-provenance.html) 2024 found that among the 999 most popular crates on crates.io,
around 17 % contained code that did **not match the code in their code repository**.

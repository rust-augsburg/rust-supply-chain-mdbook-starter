# A repeatable evaluation workflow

1. **Need** — Can the dependency be avoided?
2. **Fit** — Does its scope and API match the use case?
3. **Stewardship** — Is maintenance and governance credible?
4. **Implementation** — What code and build behavior are trusted?
5. **Graph** — What transitive dependencies and features arrive?
6. **Evidence** — What advisories, provenance, and reviews exist?
7. **Decision** — What conditions and follow-up actions apply?

> The output is not “secure.” The output is an explicit decision with known
> assumptions.

The cheapest dependency to secure is the one you do not add.

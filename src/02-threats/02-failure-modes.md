# Vulnerability, compromise, and abandonment

## Vulnerability

The published code contains an exploitable defect.

## Compromise

An attacker obtains influence over source, publishing, or the build pipeline.

## Abandonment

The crate no longer receives the maintenance needed by your production system.

These risks can coexist, and each requires different evidence.

## Speaker Notes

Also mention typosquatting, dependency confusion, malicious build scripts, and
unexpected feature changes. Avoid turning the section into a catalogue of
incidents.

## Transition

We now need a workflow that covers these dimensions without pretending to
produce certainty.

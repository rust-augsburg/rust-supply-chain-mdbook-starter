# What can go wrong?

A useful review starts with failure modes, not tool names.

| Dimension | Example question |
|---|---|
| Code | Can a defect violate security assumptions? |
| Maintainers | Could publishing authority be misused or compromised? |
| Build | What executes during compilation? |
| Dependencies | What additional trust is introduced? |
| Operations | Can we detect, update, or replace it quickly? |

## Speaker Notes

Present this as a model for asking questions, not a complete taxonomy.

Point out that accidental vulnerabilities and deliberate compromise require
different evidence and mitigations.

## Transition

Group the most common concerns into three practical categories.
